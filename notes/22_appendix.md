# 22. Appendix: A Friendly Lookup Guide

Use this page when you recognize syntax but cannot recall its name. It is a map, not a chapter to memorize. Follow the linked chapters when you need the reasoning behind a feature.

## Appendix A: Keywords

Rust has several categories of keywords. They cannot be used as variable or function names unless you escape them using a raw identifier (e.g., `r#type`).

### Keywords Currently in Use
- **Control Flow**: `if`, `else`, `match`, `while`, `loop`, `for`, `in`, `return`, `break`, `continue`.
- **Declarations**: `fn` (function), `let` (variable), `mut` (mutable), `struct`, `enum`, `trait`, `impl`, `type`.
- **Modules & Visibility**: `mod`, `use`, `crate`, `pub`, `super`.
- **Types & Context**: `self`, `Self` (the type of `self`), `where` (trait bounds), `dyn` (dynamic dispatch).
- **Async**: `async`, `await`.
- **Safety**: `unsafe` (bypassing compiler checks).

### Reserved Keywords
Reserved for future language features.
`abstract`, `become`, `do`, `final`, `override`, `priv`, `typeof`, `unsized`, `virtual`, `yield`.

### Weak Keywords
Only act as keywords in specific contexts.
- `union`: To declare a C-like union.
- `'static`: The static lifetime.

## Appendix B: Operators and Symbols

- **Arithmetic & Logical**: `+`, `-`, `*`, `/`, `%`, `&&`, `||`, `!`.
- **Bitwise**: `&`, `|`, `^`, `<<`, `>>`.
- **Type-level & Pointers**:
  - `&`: Shared reference (borrow).
  - `*`: Dereference (accessing the value behind a pointer/reference). Also used for raw pointers (`*const T`, `*mut T`).
  - `?`: Error propagation (early return if `Err` or `None`).
  - `!`: The never type (a function that never returns, like `panic!`).
- **Ranges**:
  - `..`: Exclusive range (`1..5` means 1, 2, 3, 4).
  - `..=`: Inclusive range (`1..=5` means 1, 2, 3, 4, 5).
- **Paths**: `::` (Path separator, e.g., `std::net::TcpListener`).
- **Pattern Binding**: `@` (Bind a matched value to a variable, e.g., `id @ 1..=5 => ...`).

## Appendix C: Derivable Traits

Rust can automatically generate implementations for certain traits using `#[derive(Trait)]`.

- **`Debug`**: Allows formatting using `{:?}`. The compiler synthesizes code that prints the struct name and all its fields recursively.
- **`Clone`**: Allows explicit duplication of data. The compiler synthesizes a method that calls `.clone()` on every field in the struct.
- **`Copy`**: A marker trait indicating bit-for-bit duplication is valid. If a type is `Copy`, assigning it duplicates its bits instead of moving it. This is about whether copying is safe, not literally about where the value is stored; a `Copy` type can be inside another heap allocation.
- **`PartialEq` & `Eq`**: For equality (`==`, `!=`). The compiler synthesizes code that compares each field recursively. `Eq` is a marker trait indicating full equivalence (e.g., `f32` is `PartialEq` but not `Eq` because `NaN != NaN`).
- **`PartialOrd` & `Ord`**: For ordering (`<`, `>`, `<=`, `>=`). Compares fields lexicographically (top to bottom).
- **`Hash`**: For using the type as a key in a `HashMap`. The compiler synthesizes code that feeds every field into the hasher.
- **`Default`**: Provides a `::default()` constructor. The compiler synthesizes code that calls `::default()` on every field.

## Appendix D: Useful Development Tools

Rust provides a rich, standardized toolchain out of the box (unlike TypeScript where you piece together ESLint, Prettier, ts-node, etc.).

- **`rustfmt`**: The official code formatter. Run `cargo fmt` to automatically format all code.
- **`clippy`**: An advanced static analysis linter. Run `cargo clippy`. It catches common mistakes, performance issues, and non-idiomatic code.
- **`rust-analyzer`**: The official Language Server Protocol (LSP) implementation for IDEs (VSCode, Neovim). Provides instant type-hints, auto-completion, and inline errors.
- **`cargo-expand`**: Shows the result of macro expansion. Useful for seeing the actual code generated by `#[derive(...)]` or `println!()`.
- **`miri`**: An interpreter for Rust's Mid-level Intermediate Representation (MIR). It can catch many kinds of undefined behavior, especially in `unsafe` code. It is a powerful extra check, not a proof that a program is bug-free.

## Appendix E: Editions

Rust is continuously evolved without breaking backwards compatibility.

- **Editions (2015, 2018, 2021, 2024)**: Instead of creating a "Rust 2.0" that breaks old code (like Python 3), Rust releases Editions every three years.
- **Stability without Stagnation**: An edition might introduce new keywords (like `async` in 2018) that would break older code using `async` as a variable name. 
- **The Magic**: The Rust compiler can compile a project where Crate A uses the 2015 Edition, Crate B uses the 2021 Edition, and the main binary uses the 2024 Edition. They all compile down to the same internal representation (MIR) and link together with zero runtime overhead.

## Appendix G: How Rust is Made and "Nightly Rust"

Rust's rapid, reliable development cycle is structured around the **"Train Model"**:

- **The Release Channels**:
  1. **Nightly**: Built every single night from the latest commits on the `master` branch. Unstable and experimental language features can only be activated here using `#![feature(...)]`.
  2. **Beta**: Every 6 weeks, the work from nightly branches into Beta. It spends 6 weeks undergoing regression testing and bug fixing.
  3. **Stable**: Every 6 weeks, the tested Beta branch becomes the new official Stable release (e.g., 1.80 -> 1.81).
- **RFC (Request for Comments) Process**: Every major language change or standard library addition begins as an open RFC on GitHub, debated by the entire community before implementation.
- **Toolchain Switching with `rustup`**:
  ```bash
  rustup toolchain install nightly
  rustup default nightly        # Set nightly as default system-wide
  cargo +nightly run            # Run just this project on nightly
  ```
